## MQTT 控制台客户端：修复 WithWillMessage 编译错误（REA 静态验证）

**问题**：`Program.cs` 用 `.WithWillMessage(new MqttApplicationMessageBuilder()...)`，CS1061 报错。
**根因**：项目实际引用 MQTTnet **4.2.1.781**（由 `WebJobs.Extensions.MQTT.OutputBinding 1.0.4` 传递带入），v4 的 `MqttClientOptionsBuilder` 没有 `WithWillMessage`，只有分散的 `WithWillTopic / WithWillPayload / WithWillQualityOfServiceLevel / WithWillRetain` 等。
**修复**：改为四个 `WithWill*` 链式调用；顺带给 `Console.ReadLine()` 加 `IsNullOrWhiteSpace` 判空（原来直接 `.Equals` 会 NRE）。

**验证方式**：用 REA（rea@6.4.0，`inspect-managed-artifact` / `inspect-managed-members`）对 `bin/Debug/net8.0/MQTT.dll` 做静态证据确认：
- AssemblyRef 实测只有 4 个：`System.Runtime 8.0.0.0`、`MQTTnet 4.2.1.781`、`MQTTnet.Extensions.ManagedClient 4.2.1.781`、`System.Console 8.0.0.0`。
- MemberRef 中确认存在 `WithWillTopic(0x0a000027) / WithWillPayload(0x0a000028) / WithWillQualityOfServiceLevel(0x0a000029) / WithWillRetain(0x0a00002a)`，且 `<Main>d__4.MoveNext`(0x06000008) 依次 callvirt 调用，修复已落到 IL。
- 程序集 TFM = `.NETCoreApp,Version=v8.0`，无 P/Invoke、无 ReadyToRun、纯 IL。

## 技术债 #1 已解决：依赖瘦身 49 → 3

**改动**（`MQTT.csproj`）：移除 `WebJobs.Extensions.MQTT.OutputBinding 1.0.4`，改为直引
`MQTTnet 4.3.7.1207` + `MQTTnet.Extensions.ManagedClient 4.3.7.1207`。顺带给 csproj 补了 `RootNamespace`。

**为什么不是 v5（重要，勿重复踩）**：
- MQTTnet v5 **删除了 ManagedClient 扩展**（官方 breaking change，v5.0.0 release notes 明列 "Removal of Managed Client"）。
- 作者 chkr1011 在 discussion #2162 明确回复："There is no managed client available in version 5. It is not yet planned… The best way is to build your own managed client."
- 实测 nuget.org flatcontainer：`MQTTnet.Extensions.ManagedClient` 共 99 个版本，**最新就是 4.3.7.1207，无任何 5.x**。本地缓存只有 4.2.1.781 / 4.3.7.1207。
- 所以本项目要用 ManagedClient（自动重连/心跳/断线恢复），**4.3.7.1207 就是天花板**。
- 想上 v5 只能自己写重连 + 队列（`EnqueueAsync` 那套要手搓），代价远大于收益。

**实测收益（REA + deps.json 双向确认）**：
| 指标 | 改前 | 改后 |
|---|---|---|
| deps.json 运行时库 | 49 | 3 |
| 输出目录文件数 | 34 | 7 |
| deps.json 体积 | 32,580 B | 1,758 B |
| MQTT.dll AssemblyRef | 4 | 5（多了 System.Net.Primitives 8.0.0.0） |
| 编译警告 | 1 (CS8600) | 0 |

被剔除的 46 个库全部是 `Microsoft.Azure.WebJobs(.Core) 3.0.37`、`Newtonsoft.Json 13.0.1`、18 个 `Microsoft.Extensions.* 2.1.x` —— REA 证实 MQTT.dll 从未引用它们，纯躺尸。

**功能完整性（REA MemberRef 取证，0x06000008 `<Main>d__4.MoveNext` 实际 callvirt）**：
`CreateManagedMqttClient` → `WithWillTopic` → `WithWillPayload` → `WithWillQualityOfServiceLevel` → `WithWillRetain` → `WithWillDelayInterval` → `WithAutoReconnectDelay` → `add_ApplicationMessageReceivedAsync` → `StartAsync` → `IsNullOrWhiteSpace` → `EnqueueAsync` → `StopAsync` 全部保留；
`<OnMessageReceived>d__5.MoveNext` 仍走 `get_PayloadSegment`（4.x 该属性还在，v5 才改 Payload）。

**顺带**：`Program.cs` 的 `string input` 改 `string? input`，消除最后一个 CS8600 警告，现 0 警告 0 错误。

## 技术债 #2 已解决：WillDelayInterval 抛 NotSupportedException（运行时端到端验证）

**报错**：`System.NotSupportedException: Feature 'WillDelayInterval' requires MQTT version 5.0.0.`（VS 调试器弹出）
**根因**：MQTTnet **4.x 的 `MqttClientOptionsBuilder` 默认协议版本是 `MqttProtocolVersion.V311`（MQTT 3.1.1）**，
而 `WithWillDelayInterval` 是 MQTT 5.0.0 引入的 Will Delay Interval 特性，CONNECT 报文里没有对应字段可填。
**注意**：这是**运行时**异常不是编译错误 —— 编译能过、连不上才知道。v5 把默认版本改成 V500 了，v4 没改。

**修复**（`Program.cs`）：在 options 链最前面加一行
```csharp
.WithProtocolVersion(MqttProtocolVersion.V500)  // MQTTnet 4.x 默认 V311，不声明会抛 NotSupportedException
```
`MqttProtocolVersion` 在 **`MQTTnet.Formatter`** 命名空间（不是 `MQTTnet.Protocol`，我第一次就搞错了，CS0103）。
该 using 文件里本来就有。

**环境确认（本机实测）**：EMQX 5.3.2 装在 `D:\emqx-5.3.2-windows-amd64`，`erl.exe` PID 5296 监听 1883，
Dashboard `http://127.0.0.1:18083/api/v5/status` 返回 200 `emqx is running`。
`etc/emqx.conf` 里没写 `max_mqtt_version` 限制，5.x 默认同时吃 3.1.1 和 5.0.0，所以切 V500 无副作用。

**端到端实测（0 警告 0 错误 → 真连真跑）**：异常消失，QoS1 传感器上报 + 订阅回显 + 上位机下发 + `exit` 正常退出全通：
```
【上位机下发指令】hello-cmd-1
【下位机上报】{"deviceId":"dev001","temp":26,"hum":42,"count":1}
[上位机接收传感器] 主题:device/sensor/data 数据:{...}     ← 证明 get_PayloadSegment 解码正常
【下位机收到控制指令】指令:hello-cmd-2
MQTT客户端已断开
```

**踩坑**：管道喂 stdin 时，先 `printf` 的那行常在 `Main` 进入 while 前就被读掉，不会回显 —— 看着像丢消息，其实是时序，不是 bug。

## 工具踩坑

- bash 的 `/tmp` 与 Windows python.exe 不互通（老坑又踩了一次），跨进程传文件统一用 `D:/xxx` 路径。
- bash 里 `timeout` 会解析到 **Windows 版** `TIMEOUT.EXE`，报"语法不正确"，不能当 GNU timeout 用。改用后台 `&` + `sleep` + `kill $!`，或直接靠 stdin 关闭自然退出。
- 从 Bash 调 `powershell -c ...` 会被安全策略拦截，必须用 PowerShell 工具；且 `Get-CimInstance` 查命令行在该沙箱下报 `sandbox-center cmd decisionRecord missing actual resource subject`，不可用。查进程路径改用目录扫描（已知装在 D 盘）。
- `dotnet restore` 失败信息里 `nuget-group / Microsoft Visual Studio Offline Packages / nuget-hosted` 三个源都列出来了，说明本机配了多源（含离线包目录），排查时可参考。
